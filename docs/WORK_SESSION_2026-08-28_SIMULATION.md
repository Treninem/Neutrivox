# Рабочая запись: крупный блок симуляции и диагностики

## Что сделано
Добавлен единый `SimulationWorkflowService`: проверка проекта → остановка при критических ошибках → выполнение логики → запись результата и ошибок в трассировку.

Добавлен `ProjectSnapshotService` для сохранения и восстановления состояния виртуальных каналов и тегов во время экспериментов.

Добавлена документация `SIMULATION_WORKFLOW.md`.

## Как была понята задача
Симуляция не должна быть набором несвязанных сервисов, которые интерфейс вынужден вручную соединять. Нужен единый рабочий цикл с понятным результатом.

## Почему выбран этот вариант
Оркестратор использует существующие проверки и движок логики как независимые компоненты и определяет их порядок, не дублируя правила. Снимки отделены от сохранения проекта, потому что эксперимент с виртуальными значениями не должен менять конфигурацию.

## Что это меняет
Появилась единая техническая точка входа для будущей страницы симуляции с ошибками, трассировкой и восстановлением экспериментального состояния.
