# Рабочая запись — большой интеграционный и release-блок

## Запрос пользователя
«дальше больше лучше».

## Как понята задача
Пользователь требует продолжать разработку крупными связанными блоками и делать качество важнее количества отдельных файлов. Поэтому следующий блок должен объединять UI, аппаратную связку, deployment-путь, проверки и документацию, а не создавать очередные изолированные классы.

## Проверенное текущее состояние
- Основное desktop-приложение построено на Avalonia/.NET.
- MainWindow уже содержит единое рабочее пространство проекта, оборудование, I/O, схему, подключение, логику, симуляцию и проверку.
- Discovery уже имеет отдельный экран и реальный перечень COM-портов.
- Deployment имеет preflight, safety gate, registry адаптеров и последовательный workflow.
- Для ПР100 предусмотрен отдельный путь через документированный механизм Owen Logic / Master of replication; внутренний Neutrivox payload не выдается за формат производителя.
- Release checklist уже требует фактической проверки, а не условного статуса PASS.

## Инженерное решение
Продолжать интеграцию вокруг единой модели AutomationProject. Подключение физического оборудования является состоянием существующего проекта, а не вторым режимом приложения.

## Почему
Это сохраняет главное требование пользователя: нельзя делать отдельные «проекты без прибора» и «проекты с прибором». Один проект должен сначала существовать как цифровая модель, затем быть сопоставлен с физическим устройством и после проверки использовать подтвержденный способ передачи.

## Важное ограничение
Никакой новый профиль устройства, наличие IP/COM или Modbus-ответ сами по себе не являются доказательством возможности программирования. Реальный deployment включается только при наличии документированного и проверенного adapter.

## Следующее
Следующим крупным блоком является фактическая стабилизация UI/deployment, затем полный compile/regression и Windows release.
