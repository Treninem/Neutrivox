# Работа в Neutrivox: один понятный процесс

## Главное правило

В Neutrivox существует один проект. Пользователь не выбирает отдельные режимы «с прибором» и «без прибора». Реальное оборудование можно подключить к уже созданному проекту в любой момент.

## Пошаговый процесс

### 1. Создание
Создайте проект и добавьте цифровые модели контроллеров, программируемых реле и модулей.

### 2. Настройка
Настройте каналы, параметры, соединения и будущую логику. На этом этапе физические приборы не требуются.

### 3. Проверка и моделирование
Используйте симуляцию для проверки логики и состояний. Ошибки проекта должны быть устранены до работы с реальным оборудованием.

### 4. Подключение
Подключите только то оборудование, которым вы имеете право управлять. Neutrivox показывает обнаруженные устройства и не считает IP-адрес доказательством модели устройства.

### 5. Сопоставление
Пользователь подтверждает, какой обнаруженный прибор соответствует объекту проекта. Сопоставление всегда видно перед передачей данных.

### 6. Предварительная проверка
Перед загрузкой программа проверяет проект и выбранные цели. При ошибке загрузка не должна начинаться.

### 7. Передача
Конфигурации передаются по одному устройству в понятной последовательности. После каждого устройства пользователь видит результат и может остановить процесс.

## Важное ограничение

Neutrivox не должен выполнять запись в оборудование только потому, что устройство обнаружено в сети. Для передачи конфигурации необходимы: поддерживаемый профиль устройства, проверенный способ связи, явный выбор цели и подтверждение пользователя.

## Как понять, что происходит

Интерфейс должен показывать простые статусы:
- Не подключено — проект существует только как цифровая модель.
- Обнаружено — устройство найдено, но ещё не связано с проектом.
- Сопоставлено — пользователь подтвердил соответствие.
- Готово к проверке — можно выполнить предварительную проверку.
- Готово к загрузке — все обязательные проверки пройдены.
- Загружено — операция завершена и результат зафиксирован.
