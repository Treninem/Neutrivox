## Как понята задача
Нужно продолжать разработку крупными законченными блоками. В текущей архитектуре уже были отдельные сервисы обнаружения, профили устройств, Modbus RTU и сопоставление физического устройства с объектом проекта. Следующий логичный шаг — дать пользователю один понятный экран, в котором можно увидеть доступные COM-порты, выбрать интерфейс, запустить обнаружение и увидеть реальные результаты.

## Что сделано

1. Добавлен `MainWindow.Connection.cs` с единым экраном «Подключение и обнаружение».
2. Интерфейс получает реальные COM-порты через `SerialPortInventoryService`.

6. Устройство не получает автоматически название модели только потому, что ответило по Modbus.
7. Для найденного устройства предлагается сопоставление с существующим объектом проекта.
8. Зарегистрированы документированные профили ОВЕН при инициализации connection workflow.
9. Добавлена кнопка «Подключение» в основную навигацию, не создавая отдельного проекта для физического оборудования.
10. Исправлена инициализация connection services так, чтобы discovery provider не регистрировался повторно при каждом сканировании.
11. Добавлена запись этой рабочей сессии в документацию.

## Почему выбран такой вариант

Пользователь требует, чтобы программа действительно понимала, что к ней подключено. При этом IP/COM и ответ Modbus сами по себе не доказывают конкретную модель. Поэтому экран намеренно показывает факт ответа и отдельно — состояние идентификации.

Отдельный экран «Подключение» не является дубликатом «проектирования с прибором» и «проектирования без прибора». Он представляет физическое состояние того же единого проекта. Созданный проект продолжает использоваться для схемы, логики и симуляции.

## Ограничения

Текущий Modbus discovery является read-only и не пишет конфигурацию. Поддержка программирования конкретного контроллера не объявляется только на основании наличия Modbus.

Для ПР100 официальная документация указывает USB как интерфейс программирования, а RS-485 — для Modbus-обмена; поэтому реальный загрузчик пользовательской программы должен реализовываться отдельным адаптером по документированному механизму. Это подтверждено официальными материалами ОВЕН.
