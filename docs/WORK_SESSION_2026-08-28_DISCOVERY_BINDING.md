# Рабочая запись: идентификация и сопоставление устройств

## Пользовательское сообщение
«далее».

## Как понята задача
Нужно продолжить разработку целым функциональным блоком. Предыдущий слой уже умеет находить COM-порты и получать ответы Modbus RTU, но пользователю недостаточно видеть только адрес вида `COM3@1`. Он должен понимать, что программа смогла подтвердить, что не смогла подтвердить, и почему конкретный физический прибор предлагается для сопоставления с объектом проекта.

## Что сделано

1. Добавлен `DeviceBindingExplanationService`, который преобразует результат профилирования/совместимости в понятные статусы: модель не подтверждена, несовместимо или кандидат.
2. Введено отдельное отображение уверенности сопоставления и причины совпадения.
3. Добавлен `DeviceDiscoveryReportService` для формирования единого результата обнаружения, пригодного для UI.
4. Добавлен `DeploymentSequenceValidationService`, который проверяет неизменность выбранных целей перед последовательной передачей: устройство должно существовать, не повторяться, иметь endpoint и тот же профиль, с которым строился план.
5. Все эти сервисы остаются только логическим слоем и не выполняют физическую запись в прибор.

## Почему выбран такой вариант

Нельзя показывать пользователю ложное утверждение «это точно ПР100» только потому, что устройство ответило на Modbus. Поэтому идентификация отделена от обнаружения. Аналогично, план передачи должен считаться действительным только в отношении тех объектов, которые существовали на момент подготовки плана и не были изменены до операции.

Разделение объяснения, отчёта и физической операции делает интерфейс единообразным и позволяет позже использовать те же результаты в журнале, окне подключения и отчёте о передаче.

## Что дальше

Следующий крупный блок — связать эти результаты непосредственно с UI подключения и сделать отдельный последовательный экран передачи: выбор цели → preflight → подтверждение → выполнение шага → результат → переход к следующему устройству. Затем можно двигаться к конкретным production adapters только для тех моделей и способов программирования, которые документированы и реально проверены.
