# Рабочая запись — интеграционный проход

## Запрос пользователя
«продолжим».

## Как понято
Нужно продолжать фактическую работу в репозитории крупными связанными блоками, а не ограничиваться описанием планов.

## Что проверено
Проверены текущие модели единого проекта, deployment sequence/execution, safety gate, discovery/binding и коммерческие feature gates. Подтверждено, что эти подсистемы имеют отдельные сервисы и не должны создавать второй тип проекта для работы без оборудования.

## Что изменено этим проходом
Подготовлен отдельный интеграционный слой для сводного статуса проекта и deployment. Он предназначен для подключения существующих сервисов к UI без дублирования бизнес-логики.

## Почему выбран этот вариант
`AutomationProject` должен оставаться единственным источником данных. UI получает производное состояние через фасады, а не хранит собственные копии списка устройств, логики или целей передачи.

## Ограничение
Физическая передача не считается готовой только потому, что существует план. Нужен конкретный проверенный deployment adapter для конкретного профиля устройства.

## Следующий крупный шаг
Подключение интеграционного состояния к MainWindow с полным UI последовательной передачи, затем компиляционный/CI проход и исправление найденных ошибок.
