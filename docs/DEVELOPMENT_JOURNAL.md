# Журнал разработки Neutrivox

Этот файл является постоянным журналом проекта. После каждого значимого этапа сюда должны добавляться записи: что сделано, что проверено, что планируется, какие решения рассматривались и почему выбран конкретный вариант.

---

## 2026-08-27 — Полноценный рабочий раздел оборудования

### Что сделано
- Интерфейс переработан так, чтобы центральная рабочая область показывала содержимое выбранного раздела.
- Реализован каталог оборудования непосредственно в приложении.
- Пользователь может создать проект и добавлять в него устройства из каталога.
- Добавленные устройства отображаются отдельным списком в составе проекта.
- Реализовано удаление устройства вместе со связанными соединениями.
- Для каждого добавленного устройства автоматически создаётся независимый набор каналов I/O.
- Реализован рабочий раздел «Входы и выходы» с редактированием описаний каналов.
- Реализована базовая проверка проекта с понятным результатом.
- Счётчик оборудования и текущий проект обновляются в интерфейсе.
- Разделы работают на русском и английском языках.

### Что изменилось
Neutrivox перестал быть только стартовым экраном с навигацией. Теперь существует сквозной рабочий сценарий: создать проект → выбрать оборудование → добавить его → открыть каналы → настроить описания → выполнить базовую проверку.

### Что проверено
Логика добавления и удаления оборудования отделена от интерфейса отдельным сервисом. Каналы каждого экземпляра устройства создаются отдельно, поэтому изменение одного устройства не должно изменять профиль другого экземпляра.

### Какие проблемы обнаружены
Пока интерфейс строится программно вокруг базовых элементов Avalonia. Это ускоряет создание полноценного рабочего вертикального среза, но при дальнейшем усложнении визуального редактора потребуется переход к MVVM и специализированным представлениям.

### Какое решение принято и почему
Сначала реализуется законченный рабочий путь пользователя, а затем добавляется глубокая визуальная полировка. Такой подход позволяет раньше проверять реальную логику программы и не тратить время на оформление экранов, которые позже могут измениться из-за требований функциональности.

### Что делать дальше
1. Добавить сохранение и открытие проектов через полноценный интерфейс.
2. Реализовать визуальную схему устройств и соединений.
3. Расширить проверки: конфликты адресов, совместимость интерфейсов и неполные настройки.
4. Добавить поиск и фильтрацию каталога.
5. Начать подготовку реальных профилей оборудования только по проверенной документации.
6. Перевести растущие части интерфейса на более масштабируемую MVVM-структуру.
