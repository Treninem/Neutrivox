# Рабочая запись: единая коммерческая матрица возможностей

## Пользовательский запрос
«продолжим по максимому».

## Как понят запрос
Продолжить разработку максимально большим связанным блоком, а не отдельными разрозненными изменениями. К этому моменту в проекте уже существовала коммерческая модель тарифов, но доступность возможностей была разбросана по архитектуре. Поэтому следующий логичный слой — единая матрица возможностей, которую интерфейс и будущие рабочие сценарии смогут использовать одинаково.

## Что сделано

1. Добавлен `CommercialFeatureCatalogService` с перечнем функций и RU/EN описаниями.
2. Добавлен `CommercialFeatureMatrixService`, определяющий доступность функции для Free/Standard/Professional/Business/Owner.
3. Добавлен `FeatureAccessService` для пользовательского результата проверки доступа с русским и английским сообщением.
4. Сохранена отдельная коммерческая модель планов с ценами в рублях и персональной бессрочной Owner-лицензией, не выставляемой на продажу.

## Почему выбран этот вариант

Функции не должны самостоятельно решать, какая редакция им нужна. Единый каталог уменьшает дублирование и позволяет одному и тому же правилу использоваться в интерфейсе, проверках и позже в службах передачи. Русское и английское описание хранится рядом с функцией, чтобы локализация была частью модели, а не случайным текстом конкретного окна.

Приоритет редакций централизован, поэтому изменение коммерческой политики не требует переписывания каждого экрана.

## Что ещё необходимо проверить

Текущая лицензия и feature gate — архитектурный слой, а не завершённый платёжный backend. В будущем нужно связать активную лицензию пользователя с этим матричным доступом, а серверную проверку подписей и выпуск ключей держать вне клиентского репозитория.

## Следующий крупный блок

Интегрировать feature access в UI настроек/лицензии и рабочие действия: при недоступной функции пользователь должен увидеть понятное RU/EN объяснение и способ перейти к легальной активации. После этого — завершить production deployment adapter для конкретной подтверждённой модели и перейти к полному regression/CI проходу.
