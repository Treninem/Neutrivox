# Стратегия тестирования Neutrivox

## Цель

Neutrivox развивается как единый проект автоматизации, поэтому проверка должна подтверждать не отдельные экраны, а целые рабочие цепочки: создание проекта, оборудование, I/O, логика, диагностика, симуляция и подготовка к физической передаче.

## Уровни проверки

### 1. Модели и сервисы
Проверяются создание устройств, уникальность имён, ссылки логики, валидация соединений, выполнение инструкций и восстановление снимков.

### 2. Рабочие сценарии
Проверяются цепочки действий пользователя:

- создать проект → добавить оборудование → настроить I/O;
- создать логику → проверить → выполнить симуляцию;
- сохранить состояние → изменить виртуальные входы → восстановить состояние;
- обнаружить ошибки → убедиться, что симуляция не продолжает работу при критических проблемах.

### 3. Регрессия
Перед выпуском изменения не должны удалять поддержку уже работающих проектов и функций без явного решения владельца проекта.

### 4. Реальное оборудование
Физические операции тестируются только через подтверждённые адаптеры и поддерживаемые модели. Симуляция не считается доказательством совместимости с конкретным прибором.

## Принцип

Нельзя выдавать неподтверждённую функцию за протестированную. Перед финальным установщиком должна быть проведена отдельная полная проверка сборки и чистой установки.
