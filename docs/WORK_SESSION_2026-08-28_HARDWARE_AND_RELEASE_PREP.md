## Как понята задача
Работать крупным вертикальным блоком: не добавлять очередные абстракции ради количества файлов, а одновременно укрепить реальные аппаратные основания, повторяемую Windows-сборку и финальную документацию.

## Что сделано

### 1. Повторная проверка официальной документации ОВЕН
Проверены актуальные страницы ОВЕН по ПР100 и Owen Logic. Зафиксировано:
- ПР100 программируется в Owen Logic;
- для программирования используется microUSB/USB-подключение;
- RS-485 у соответствующих модификаций предназначен для Modbus RTU/Modbus ASCII;
- в документации Owen Logic описана отдельная команда записи программы в подключённый прибор.

### 2. Разделение возможностей
Введено явное инженерное правило:
`Device profile -> Communication capability -> Verified programming/deployment capability`.
Наличие COM-порта, IP-адреса или Modbus-ответа не переводит профиль в состояние готовности физической загрузки.

### 3. Windows build preparation
Добавлен `scripts/Build-Windows.ps1`:
- restore solution;
- Release build;
- build/run smoke test;
- self-contained `win-x64` publish;
- single-file publish;
- отдельный output-каталог `artifacts\windows`.

### 4. Installer preparation
Добавлен `installer/Neutrivox.iss` для Inno Setup. Исправлен постоянный application GUID до корректного формата.
Это пока описание сборки установщика, а не доказательство того, что установщик уже собран на чистой машине.

### 5. User message logging
Сообщение пользователя `«дальше больше лучше»` записано в `docs/USER_MESSAGE_LOG/2026-08-28_2351.md` как отдельное требование процесса.

## Почему так
Сейчас критически важно перейти от архитектурных заготовок к воспроизводимой сборке. При этом нельзя реализовать воображаемый протокол загрузки ПР100: документация подтверждает программирование через Owen Logic, но не предоставляет нам готовую спецификацию внутреннего бинарного протокола, позволяющую честно заявить полноценный независимый production uploader.

Поэтому подготовлен repeatable packaging layer и отдельный документ verified hardware facts, а production adapter остаётся заблокированным до подтверждения точного формата/обмена.
