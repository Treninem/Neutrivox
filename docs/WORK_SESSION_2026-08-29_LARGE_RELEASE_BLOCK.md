# Рабочая запись — крупный release/deployment блок

## Запрос пользователя
«дальше больше лучше».

## Как понято
Нужно не останавливаться на описании планов и не дробить работу на микроскопические изменения. В один рабочий блок объединять несколько тесно связанных частей: проверенные внешние факты, кодовые контракты, сборку/релиз и документацию.

## Что сделано

1. Проверена актуальная официальная документация ОВЕН по ПР100 и Owen Logic.
2. Подтверждено, что Owen Logic использует графический FBD, а Мастер тиражирования создаёт отдельный файл для записи программы без участия Owen Logic.
3. Зафиксировано жёсткое ограничение: тиражирование выполняется только между одинаковыми модификациями прибора.
4. Зафиксированы документированные параметры Мастера тиражирования `/silent`, `/ip:`, `/portname:` и `/password:`.
5. Добавлен `OwenReplicationCommandBuilder` для единого построения этих аргументов.
6. Добавлен `OwenReplicationOutputParser`, который разбирает stdout/stderr консервативно и не объявляет успех только по наличию числа или строки.
7. Добавлена документация `OWEN_REPLICATION_INTEGRATION.md` с полным контрактом интеграции.
8. Добавлен Windows Release workflow: restore → Release build → smoke build/run → Windows publish → ZIP artifact → GitHub Release для тегов.

## Почему выбрано так

Вместо попытки воспроизвести закрытый формат Owen Logic используется документированный официальный механизм Мастера тиражирования. Это одновременно сохраняет техническую правдивость, совместимость с документированным способом работы и не создаёт обходов чужой защиты.

Командный builder вынесен отдельно, чтобы UI и deployment workflow не собирали аргументы вручную в разных местах. Parser вынесен отдельно, чтобы внешний процесс можно было тестировать независимо от интерфейса.

Release workflow добавлен сейчас, потому что финальная сборка должна быть воспроизводимой, а не делаться вручную в последний момент.
