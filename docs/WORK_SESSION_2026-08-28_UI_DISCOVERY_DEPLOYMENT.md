# Рабочая запись 2026-08-28 — UI, discovery и последовательная передача

## Что сделано

Добавлены UI-facing модели для симуляции, единый сервис просмотра текущих виртуальных значений и отдельный сервис формирования кандидатов сопоставления обнаруженного оборудования с документированными профилями.

Подготовлена архитектура последовательной передачи проекта через интерфейс `IDeviceDeploymentAdapter`: план должен быть заранее подтверждён, затем цели обрабатываются строго по одной. Если для конкретной модели нет проверенного загрузочного адаптера, операция не маскируется под успешную передачу.

Расширена CI-проверка smoke-сценарием для симуляции, сохранения проекта, endpoint validation и наличия проверенных профилей.

## Как понята задача

Пользователь требует, чтобы программа не просто имела внутренние сервисы, а реально сводила их в единый рабочий путь: проект → логика → симуляция → обнаружение → понимание, какой прибор подключён → конкретный выбранный прибор → поочерёдная передача.

## Почему выбран такой вариант

Слой UI получает готовые модели состояния вместо копирования бизнес-правил. Поэтому интерфейс не должен сам решать, что считается корректным устройством или можно ли проводить передачу.

Распознавание отделено от привязки: совпадение по производителю/модели создаёт кандидата для проверки, но не меняет проект автоматически. Это соответствует требованию понимать подключённое устройство, не превращая одно предположение в опасное автоматическое действие.

Последовательная передача отделена от discovery и planning. Это позволяет сначала увидеть и подтвердить план, а затем обрабатывать цели одна за другой и отдельно показать результат каждой операции.

## Что проверено

CI на момент записи запущен и проверяет обновлённый проект; окончательный результат конкретного нового запуска должен быть подтверждён после завершения workflow. Ранее в репозитории уже существовали smoke-проверки, которые охватывают симуляцию и сериализацию.

## Что осталось

Нужно закончить пользовательский интерфейс для симуляции и discovery, добавить фактические transport providers, а для каждой модели — только реально подтверждённые read/write/deployment adapters. После этого потребуется полноценный набор автоматических тестов и финальная сборка установщика.

## Следующее крупное направление

Сделать реальный экран «Подключённые устройства»: область поиска, endpoint, протокол, производителя/модель, уверенность распознавания, сравнение с профилем, явное сопоставление и кнопка перехода к подготовке последовательной передачи.
