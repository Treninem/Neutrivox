# Статус реализации Neutrivox

## Цель версии 0.2.0

Получить цельный Windows MVP/релиз-кандидат: проектирование и моделирование без физических приборов, каталог оборудования, сохранение/восстановление, логика и симуляция, безопасное обнаружение/сопоставление реального оборудования, коммерческое лицензирование и воспроизводимая Windows-упаковка.

## Состояние этапов

### Этап 1 — Основа приложения и архитектура — завершён
Avalonia/.NET 8, единый проект, доменные модели, RU/EN, сервисная архитектура.

### Этап 2 — Оборудование и I/O — завершён для цифрового проектирования
Каталог точных ПР100 и семейных профилей ОВЕН/Siemens/Schneider/Mitsubishi/OMRON/Delta/WAGO/Allen-Bradley/Beckhoff/Weintek. Семейные профили не выдумывают точное I/O.

### Этап 3 — Сохранение, открытие и recovery — завершён
`.neutrivox` Open/Save/Save As подключены к UI. Добавлен периодический recovery-снимок на диске между запусками.

### Этап 4 — Единое рабочее пространство — завершён на уровне MVP
Оборудование, связи, свойства выбранного устройства и состояние физической привязки отображаются из одной модели проекта.

### Этап 5 — Редактор логики — завершён на уровне MVP
Сети, переменные, инструкции, выбор символов и проверка логики работают внутри проекта.

### Этап 6 — Симуляция и отладка — завершён на уровне MVP
Старт/пауза/стоп, ручное изменение входов, цикл логики, выходы и trace работают без оборудования.

### Этап 7 — Диагностика и release pre-check — завершён
Страница Проверка использует ProjectHealth, LogicValidation и ReleaseReadiness, а не отдельную заглушку.

### Этап 8 — Обнаружение и сопоставление физических устройств — завершён на уровне безопасного MVP
Есть COM/Modbus RTU и явно ограниченный TCP/502 discovery, отмена, документированные профили, совместимость и отдельное подтверждение привязки. Доступный endpoint не считается автоматически известной моделью.

### Этап 9 — Последовательная физическая передача — программный workflow завершён, аппаратная сертификация по моделям продолжается
Реализованы выбор целей, preflight, safety gate, fingerprint устаревшего плана, явное `DEPLOY`, последовательное выполнение, отмена и журнал. Есть интеграционная точка с официальной Owen Logic Replication Utility. Однако read/write остаётся заблокированным для профилей, которые не прошли реальную аппаратную проверку — это намеренное правило безопасности, а не незавершённая заглушка UI.

### Этап 10 — Лицензирование и упаковка — завершён для MVP
7-дневный Professional trial, Free fallback, RUB-планы, RSA-подписанные ключи, device binding, owner issuer tool, настройки, единая версия 0.2.0, Windows single-file publish, Inno Setup, CI package/release workflows.

## Что ещё требует физического стенда

Следующие пункты невозможно честно закрыть программными тестами:

- подтверждение реальной загрузки программы в каждую конкретную модель контроллера;
- проверка поведения при потере связи/питания во время записи;
- проверка конкретных версий официальных vendor-утилит и прошивок;
- подтверждение электрических/протокольных особенностей каждой аппаратной модификации.

До прохождения такого стенда соответствующий профиль остаётся `ModelProfiled`, а физическая запись для него блокируется.

## Статус релиза

0.2.0 считается готовым цифровым MVP после успешного CI build + smoke + Windows package check. Аппаратная read/write-поддержка включается отдельно только после стендовой проверки конкретного профиля/адаптера.
