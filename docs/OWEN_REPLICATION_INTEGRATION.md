# Интеграция Neutrivox с Мастером тиражирования ОВЕН

## Цель

Neutrivox должен управлять подготовкой и запуском документированного механизма передачи программы, не копируя закрытый формат программы Owen Logic и не выдавая собственный JSON-payload за прошивку ОВЕН.

## Поддержанный сценарий

1. Проект создаётся и проверяется в Neutrivox.
2. Пользователь выбирает точную модель и модификацию.
3. Программа работает без оборудования в режиме проектирования и симуляции.
4. После подключения устройство обнаруживается и сопоставляется с экземпляром проекта.
5. Перед передачей выполняются compatibility/preflight/safety проверки.
6. Пользователь явно подтверждает конкретную цель.
7. Neutrivox запускает установленный документированный Мастер тиражирования ОВЕН.
8. Для Ethernet передаётся `/ip:`, для USB — `/portname:`; при необходимости может использоваться `/password:`.
9. stdout/stderr можно перенаправлять в файлы для отображения прогресса и ошибок.
10. Результат сохраняется отдельно для конкретного прибора.

## Жёсткое ограничение

Тиражирование разрешается только при совпадении целевой модификации с проектом. Наличие одинакового семейства устройства недостаточно.

## Безопасность

Neutrivox не должен:

- извлекать программу из прибора;
- обходить защитные ключи;
- подменять встроенный формат прошивки;
- запускать физическую запись без явного подтверждения пользователя;
- автоматически отправлять одну конфигурацию во все найденные устройства.

## Реализация

`OwenReplicationCommandBuilder` отвечает только за построение документированных аргументов.

`OwenReplicationOutputParser` осторожно интерпретирует stdout/stderr и не превращает произвольный текст в доказательство успешной записи.

Фактический запуск внешнего мастера должен оставаться отдельным adapter-слоем с контролем таймаутов, отмены, exit code и итогового статуса.
