# Рабочая запись: матрица тестирования симуляции

## Пользовательское сообщение
«далее».

## Как понята задача
Нужно продолжать не отдельными декоративными изменениями, а закрывать целый связанный пользовательский сценарий. На этом участке уже существовали ручная симуляция, сценарии и снимки. Следующим логичным шагом стала воспроизводимая автоматическая проверка ожидаемых выходов и единая фасадная точка для интерфейса.

## Что сделано

1. Добавлен `SimulationScenarioWorkflowService` для запуска именованных сценариев через общий simulation pipeline.
2. Добавлен `SimulationTestMatrixService` для выполнения набора детерминированных виртуальных тестов и сравнения ожидаемых и фактических значений выходов.
3. Добавлен `ProjectWorkflowFacade`, который собирает в один снимок сводку проекта, readiness, diagnostics, представление редактора логики и текстовый отчёт.

## Почему выбран такой вариант

Ручной запуск удобен для интерактивной работы, но для регрессии недостаточен. Матрица тестов позволяет воспроизводить одинаковые входы и проверять конкретные ожидаемые результаты без физического оборудования.

Фасад добавлен отдельно от существующих сервисов, чтобы интерфейс не содержал свою копию бизнес-правил и не создавал отдельные дублирующие разделы для одних и тех же данных.

## Что это меняет

Появилась техническая база для экрана «Тесты/Сценарии» и для автоматической регрессионной проверки логики до перехода к физическому оборудованию.

## Что дальше

Следующим крупным блоком нужно встроить в интерфейс обнаружение и сопоставление физических устройств, после чего подключать реальные transport adapters только для профилей с подтверждёнными возможностями записи.
