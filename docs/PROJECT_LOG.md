# Журнал разработки Neutrivox

Этот журнал ведётся для сохранения контекста между этапами разработки.

## Текущее состояние

Создано единое ядро проекта, каталог оборудования, конфигурация каналов, автономная симуляция, базовый движок логики и рабочее пространство.

## Последние изменения

- Добавлен каталог символов, объединяющий I/O, теги и логические переменные.
- Добавлено управление логическими переменными.
- Добавлена проверка корректности связей между устройствами.
- Создана дорожная карта из десяти этапов.
- Добавлены шаблоны типовой базовой логики.
- Добавлена проверка готовности логики к выполнению/последующей передаче.

## Почему выбран такой порядок

Сначала создаётся общая модель проекта и возможность безопасно проверить её без оборудования. Затем развиваются визуальные редакторы. Подключение и передача в реальные приборы строятся только поверх проверенной модели, чтобы не смешивать редактирование проекта с операциями на физическом оборудовании.

## Ближайшие задачи

1. Завершить интерактивный интерфейс редактора логики.
2. Улучшить визуальное рабочее пространство.
3. Связать диагностику проекта, логику и симуляцию в единый пользовательский сценарий.
4. После этого перейти к обнаружению поддерживаемого оборудования и адаптерам реальных протоколов.

## Принцип проекта

Ни одно действие симуляции или редактирования не должно самостоятельно изменять физическое оборудование. Реальные операции требуют отдельного явного выбора устройства и подтверждения пользователя.
