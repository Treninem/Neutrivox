# Рабочая запись: обнаружение и профили оборудования

## Что сделано

Добавлены контракты транспортных адаптеров, проверка области сетевого поиска и координатор обнаружения. Поиск теперь концептуально разделён на проверку области → запуск зарегистрированных провайдеров → сопоставление с документированными профилями → предложение кандидата.

## Как понята задача

Пользователь требует, чтобы Neutrivox действительно видел подключённые приборы, различал IP-адреса и понимал, что именно подключено. Для этого недостаточно простой проверки доступности IP: нужно получать признаки идентификации и сопоставлять их с каталогом известных устройств.

## Почему выбран этот вариант

IP-адрес является только адресом узла и не доказывает модель. Поэтому обнаружение не должно автоматически превращать адрес в конкретный прибор. Профиль считается подходящим только при наличии достаточных признаков, а автоматическая привязка к проекту не выполняется.

## Что уже подтверждено в репозитории

Для ПР100 существуют отдельные документированные варианты, отличающиеся I/O и наличием RS-485. Для ПМ210 зафиксировано назначение сетевого шлюза. При этом возможность загрузки пользовательской программы пока намеренно не заявляется как реализованная только на основании Modbus.

## Что осталось

Нужны реальные транспортные провайдеры для поддерживаемых способов связи, получение идентификации по официально документированным механизмам, пользовательский экран обнаружения и явное подтверждение сопоставления.

## Следующий шаг

Реализовать слой адаптеров с безопасными тестовыми и реальными режимами, а затем подключить его к интерфейсу оборудования. Перед объявлением поддержки конкретного протокола проверять его по официальной документации и тестировать на совместимом оборудовании.
