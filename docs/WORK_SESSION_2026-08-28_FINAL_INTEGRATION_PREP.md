# Рабочая запись — финальная интеграционная подготовка

## Запрос пользователя
«далее» — продолжать работу крупными связанными блоками.

## Что проверено
Текущий проект уже содержит единый `AutomationProject`, каталог устройств, I/O, схему, логику, симуляцию, discovery, физическое сопоставление, preflight/safety gate, последовательный deployment и коммерческие модели. `MainWindow` пока содержит значительную часть интерфейсной логики непосредственно в code-behind, поэтому следующий этап должен быть направлен на интеграцию и устранение технического долга, а не на бесконечное размножение сервисов.

## Что сделано в этом заходе
- Зафиксирован отдельный интеграционный документ, чтобы не выдавать незапущенную проверку за успешную сборку.
- Зафиксирована необходимость проверять фактический compile/CI результат перед финальным релизом.
- Зафиксировано, что последний известный workflow собирает `Neutrivox.sln`, smoke test и запускает smoke test на Windows runner.
- Зафиксировано, что production deployment нельзя считать завершённым без конкретного проверенного адаптера.

## Почему выбран этот порядок
Сейчас наиболее ценно получить объективный снимок состояния сборки и устранить реальные несоответствия API/моделей. Новые абстракции без compile-проверки только увеличат технический долг.

## Следующий блок
1. Получить состояние CI после последних коммитов.
2. При наличии ошибок исправлять их группой, а не по одной строке.
3. После зелёной сборки выполнить полный smoke/regression проход.
4. Затем завершать UI deployment и финальную упаковку.

## Статус
Это подготовительный этап интеграции; финальная готовность продукта пока не заявляется.
