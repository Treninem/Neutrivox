# Как устроена работа в Neutrivox

## Один проект

В Neutrivox нет отдельных режимов «работа без прибора» и «работа с прибором». Пользователь всегда работает с одним проектом.

**Почему:** проектирование не должно дублироваться. Цифровая модель и реальная привязка являются состояниями одного и того же проекта.

## Полный рабочий сценарий

### 1. Создание проекта
Создаётся единый проект автоматизации. На этом этапе физические приборы не обязательны.

### 2. Добавление оборудования
Из каталога выбираются поддерживаемые модели. Их каналы становятся частью проекта и доступны в схеме и логике.

### 3. Настройка входов, выходов и внутренних значений
Каналам задаются понятные названия и описания. При необходимости используются теги для внутренних состояний.

### 4. Логика
Настраиваются каналы, переменные и программа. Логика должна использовать символы текущего проекта, а типовые шаблоны остаются редактируемыми.

### 5. Проверка
Перед выполнением Neutrivox проверяет известные ошибки ссылок, конфликты имён и согласованность проекта. Программа не должна молча менять пользовательские данные.

### 6. Моделирование
Запускается симуляция без физического оборудования. Пользователь может менять виртуальные входы, запускать повторяемые сценарии и сохранять снимки состояния для экспериментов.

### 7. Диагностика
Результаты проверки и выполнения должны быть показаны понятным образом: что произошло, где возникла проблема и какое действие требуется.

### 8. Реальное оборудование
Когда оборудование подключено, программа использует только подтверждённые механизмы обнаружения для поиска поддерживаемых устройств. Найденный прибор не заменяет объект проекта автоматически: пользователь подтверждает сопоставление.

### 9. Подготовка передачи
Перед любой реальной передачей выполняется предварительная проверка выбранного устройства. План операции должен показывать конкретную цель и ожидаемый порядок действий.

### 10. Последовательная операция и проверка результата
Конфигурации предназначаются конкретным устройствам и обрабатываются последовательно, а не отправляются одновременно во всё найденное оборудование. После операции пользователь видит результат каждого шага.

## Почему так

Один рабочий процесс проще для пользователя, уменьшает количество дублирующихся экранов и позволяет подготовить проект полностью до появления физического оборудования. Разделение симуляции и реальных операций при этом сохраняет безопасность и контроль пользователя.
