# Рабочая запись — release gate

## Запрос пользователя
«далее» — продолжать разработку крупными блоками.

## Что сделано
Создан `docs/RELEASE_GATE_CHECKLIST.md` — единый контрольный список финального выпуска. В него включены сборка, smoke/regression, единый пользовательский workflow, физическое обнаружение, binding, preflight, safety gate, последовательный deployment, лицензирование, RU/EN, безопасность, документация и Windows installer.

## Как понята задача
Финальный выпуск должен проверяться как продукт целиком, а не как набор отдельных классов. Поэтому чек-лист охватывает путь от создания проекта без прибора до физической передачи и чистой установки.

## Почему выбран этот вариант
Ранее в проекте появился большой набор сервисов, но без единой точки выпуска легко получить ситуацию, когда отдельная часть работает, а приложение целиком не собирается или интерфейс не проходит полный пользовательский сценарий. Контрольный список создаёт один критерий готовности.

## Важные ограничения
- Никакая физическая операция не считается готовой без проверенного production adapter.
- Коммерческий план не является доказательством технической поддержки устройства.
- Непроверенный протокол не объявляется рабочим.
- Секреты лицензирования не должны находиться в публичном клиентском репозитории.

## Следующее
Фактически проверить текущую сборку и устранить найденные compile/CI ошибки крупным интеграционным проходом. Затем продолжить к финальному Windows package.

## Статус
Контрольная инфраструктура добавлена. Сам продукт пока не объявляется финально готовым.
