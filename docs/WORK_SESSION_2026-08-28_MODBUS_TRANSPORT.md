# Рабочая запись: транспорт и идентификация Modbus RTU

## Сообщение пользователя
«далее».

## Как понята задача
После добавления общего discovery и профилей нужен реальный транспортный слой. Он должен позволять Neutrivox работать с явно выбранным последовательным endpoint, выполнять только определённую протокольную операцию и возвращать проверяемый результат. При этом наличие Modbus нельзя автоматически считать доказательством возможности загрузки программы контроллера.

## Что сделано

1. Добавлен `ModbusRtuTransportService`.
   - принимает конкретный COM-порт и параметры линии;
   - открывает только явно указанный endpoint;
   - передаёт сформированный RTU-кадр;
   - ограничивает тайм-аут и размер буфера;
   - возвращает продолжительность, ответ и ошибку.

2. Добавлен `ModbusIdentificationService`.
   - использует отдельную операцию чтения;
   - проверяет CRC;
   - проверяет адрес slave;
   - проверяет ожидаемую функцию;
   - не выполняет запись.

3. Добавлен `ModbusAddressProbeService`.
   - выполняет ограниченный последовательный read-only probe диапазона slave-адресов;
   - не записывает регистры;
   - имеет ограничение размера диапазона.

## Почему выбран этот вариант

Низкоуровневый транспорт должен быть отделён от идентификации и от профилей устройств. Тогда один механизм связи можно использовать для разных документированных профилей, а профиль будет определять, какие адреса и регистры допустимы.

Разделение также предотвращает опасную ошибку: «устройство ответило по Modbus → значит это нужный контроллер → можно загружать программу». Это три разные проверки.

## Важное ограничение

Текущий `ModbusIdentificationService` не угадывает адреса регистров конкретного устройства. Он принимает их параметрами. Для настоящего распознавания конкретной модели адреса и формат идентификации должны быть указаны в подтверждённом профиле по официальной документации.

## Следующий крупный блок

Подключить документированные профильные interrogation-правила к discovery: найденный COM/endpoint должен проверяться конкретными профилями, после чего пользователь увидит модель, вариант, качество совпадения и сможет явно сопоставить её с объектом проекта. Затем — безопасная цепочка подготовки реальной передачи.
