# Журнал решений Neutrivox

Этот файл фиксирует важные архитектурные решения, их причины и последствия.

## Единый проект вместо отдельных режимов

**Решение:** симуляция, проектирование и работа с реальным оборудованием используют одну модель проекта.

**Причина:** отдельные режимы создают копии данных и усложняют интерфейс.

**Последствие:** физический прибор связывается с существующим устройством проекта только после подтверждения пользователя.

## Структурированный редактор логики

**Решение:** логика строится из типизированных операций, сетей и известных символов проекта.

**Причина:** это позволяет проверять ошибки до моделирования и не выполнять произвольный код как часть проекта.

**Последствие:** новые блоки логики добавляются через расширение каталога операций и движка выполнения.

## Реальное оборудование отделено от симулятора

**Решение:** симуляция никогда сама не передаёт команды физическим устройствам.

**Причина:** проектирование и отладка должны быть безопасны до явного перехода к операции загрузки.

**Последствие:** для реальной передачи используются отдельные подтверждённые операции и предварительные проверки.
