# Рабочая запись — крупный интеграционный проход

## Запрос пользователя
«далее» — продолжать работу крупными блоками.

## Что проверено
- `MainWindow` уже объединяет проект, оборудование, схему, логику, симуляцию и подключение в едином пользовательском пространстве.
- `AutomationProject` остаётся общей моделью оборудования, соединений, тегов и логики.
- Discovery и physical binding разделены.
- Deployment имеет отдельные preflight, safety gate, sequence и execution слои.
- Лицензии имеют отдельный каталог планов и feature access.
- Smoke test уже покрывает симуляцию, сохранение/восстановление, endpoint validation, профили ОВЕН и активацию привязанной лицензии.

## Важное обнаружение
Перед финальным релизом нельзя считать приложение готовым только по наличию большого количества сервисов. Нужно выполнить фактический compile/CI pass и устранить все ошибки интеграции, включая возможные несовпадения моделей и старые API.

## Почему выбран этот порядок
Накопленная архитектура уже достаточно крупная, поэтому следующий полезный шаг — проверка связности и сборки, а не дальнейшее бесконтрольное добавление новых параллельных абстракций.

## Следующие действия
1. Проверить compilation/CI.
2. Исправить реальные ошибки найденного прохода.
3. Интегрировать готовые presentation/state сервисы без дублирования данных.
4. После стабильной сборки завершить подтверждённый production adapter.
5. Собрать финальный Windows пакет и выполнить выпускные проверки.
