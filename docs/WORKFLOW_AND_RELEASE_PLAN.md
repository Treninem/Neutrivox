# Сквозной план разработки и выпуска Neutrivox

## Принцип крупных блоков

Каждый следующий блок должен завершать целый пользовательский сценарий, а не добавлять изолированный класс без применения. После реализации блока проверяется совместимость с существующим проектом и фиксируются результаты в истории разработки.

## Блок A — Редактор логики

Пользователь создаёт сеть, добавляет операции, выбирает символы текущего проекта, получает ошибки до запуска и видит готовность логики. Все действия работают с тем же `AutomationProject`, что оборудование и схема.

**Готовность блока:** интерфейс позволяет выполнить полный базовый сценарий без ручного редактирования внутренних объектов.

## Блок B — Симуляция и диагностика

Пользователь задаёт виртуальные значения, запускает сценарий, видит результат, события и ошибки, может повторить сценарий и восстановить снимок.

**Готовность блока:** симуляция доступна из основного рабочего процесса и не требует физического прибора.

## Блок C — Сохранение и восстановление

Проект сохраняется в устойчивом формате с проверкой версии и понятными ошибками загрузки. Восстановление после сбоя не заменяет обычное сохранение.

## Блок D — Реальные профили устройств

Для каждой поддерживаемой модели фиксируются проверенные возможности, каналы, интерфейсы и ограничения. Неподтверждённые данные не представляются как поддержка.

## Блок E — Обнаружение и сопоставление

Обнаружение собирает доступные данные через отдельные адаптеры. Пользователь видит найденные устройства и сам подтверждает сопоставление с объектами проекта.

## Блок F — Передача в оборудование

Подготовка → проверка совместимости → выбор одного конкретного устройства → понятное подтверждение → передача → результат. Несколько устройств обрабатываются последовательно с отдельным отчётом.

## Блок G — Лицензирование и версии

Бесплатная базовая версия остаётся полезной. Расширенные возможности привязываются к прозрачным лицензиям. Внешние продавцы могут распространять ключи без встроенной зависимости от конкретной торговой площадки.

## Блок H — Финальная локализация и документация

RU/EN покрывают интерфейс и руководство. Термины проверяются на понятность, а пользовательские инструкции описывают полный путь от нового проекта до безопасной передачи.

## Блок I — Проверка выпуска

Автоматические проверки, ручные сценарии, чистая установка, обновление и проверка установщика. Только после этого формируется релизный пакет.

## Критерий завершения

Neutrivox считается готовым не после появления всех кнопок, а после прохождения полного проверяемого сценария: создать проект → добавить оборудование → настроить I/O → создать логику → проверить → смоделировать → сохранить → при наличии подтверждённой поддержки обнаружить и сопоставить устройство → подготовить и выполнить явную передачу → получить отчёт.
