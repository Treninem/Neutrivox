# Рабочая запись: коммерческая модель и локализация

## Сообщение пользователя

Продолжить разработку по максимуму.

## Как понята задача

Продолжение должно давать не отдельную мелочь, а цельный блок продукта. На текущем состоянии уже существуют коммерческие модели и механизм проверки лицензии, поэтому следующий логичный слой — централизовать право доступа к функциям и подготовить реальные пользовательские документы на двух языках.

## Что сделано

1. Добавлен `LicenseFeatureGateService` как единая точка определения доступности функций для Free/Standard/Professional/Owner.
2. Добавлен `LocalizationService` для централизованного переключения RU/EN в программно создаваемом UI.
3. Добавлено русское пользовательское руководство `USER_GUIDE_RU.md`.
4. Добавлено английское пользовательское руководство `USER_GUIDE_EN.md`.
5. Добавлен `COMMERCIAL_MODEL_RUB.md` с текущей моделью цен, назначением планов и схемой продажи ключей через GGSEL.

## Почему принято такое решение

Функциональные ограничения нельзя дублировать в каждой кнопке интерфейса: одно и то же правило должно одинаково действовать в UI и внутренних сервисах. Аналогично цены нельзя зашивать в экраны — они должны оставаться в каталоге планов.

Русский и английский интерфейсы нужны как часть продукта. Документация на обоих языках должна использовать тот же терминологический смысл, чтобы пользователь мог перейти между языками без изменения рабочего сценария.

GGSEL рассматривается только как внешняя точка продажи. Ядро приложения не должно зависеть от магазина для выполнения базовой логики лицензии.

## Что сознательно не сделано фиктивно

Не добавляется «готовый» сервер GGSEL без реального API или конфигурации продавца. Не добавляются секретные ключи подписи в публичный репозиторий. Не заявляется, что наличие лицензии само по себе подтверждает совместимость с физическим устройством.
