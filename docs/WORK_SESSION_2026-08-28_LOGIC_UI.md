# Рабочая запись: интеграция редактора логики в интерфейс

## Пользовательское сообщение
«далее».

## Как понята задача
Продолжить работу крупным функциональным блоком и не оставлять уже созданные backend-сервисы отдельными заготовками. Редактор логики должен быть доступен из основного окна и работать внутри единого проекта, без отдельного режима «с прибором» и «без прибора».

## Что сделано

1. Навигация кнопки «Логика» переведена на отдельный обработчик и связана с новым представлением редактора.
2. Создан `MainWindow.Logic.cs` как отдельная часть partial-класса, чтобы не раздувать существующий файл окна и не дублировать проектное состояние.
3. В интерфейс добавлены создание сети и создание переменной.
4. В интерфейс выведена панель доступных логических операций из существующего toolbox.
5. Добавлено отображение сетей и их инструкций.
6. Для инструкций сделано редактирование цели, источника A, источника B и комментария.
7. Добавлено удаление логических переменных.
8. В интерфейс выведен каталог символов текущего проекта, чтобы пользователь видел реальные I/O, теги и переменные, доступные логике.
9. Добавлен запуск проверки логики прямо из редактора с выводом ошибок, предупреждений и информации.
10. Добавлено отображение общей сводки проекта в редакторе.

## Почему выбран такой вариант

`MainWindow.cs` уже содержит основной жизненный цикл окна и проектное состояние. Логику редактора вынес отдельно через partial-класс, потому что редактор будет развиваться значительно быстрее остальных экранов. При этом данные остаются едиными: редактор получает тот же `AutomationProject`, что оборудование и схема.

Отдельный полноценный экран симуляции пока не создаётся как второй проект. Существующий `SimulationWorkflowService` уже рассчитан на тот же проект, поэтому следующим шагом он будет подключён к этому рабочему процессу.

## Что обнаружено и исправлено

В первом варианте интеграции удаление переменной было ошибочно привязано к отсутствующему методу workflow-фасада. Ошибка исправлена через существующий `LogicProjectService`, где удаление уже реализовано. Это сделано вместо добавления дублирующей логики.

## Ограничения текущего блока

Редактор пока не является промышленным полноценным графическим LAD/FBD-редактором: текущая версия работает через структурированные карточки и поля. Это сознательная промежуточная интеграция, которая сначала подключает реальную модель данных и проверку, после чего визуальный редактор можно развивать поверх стабильного ядра.
